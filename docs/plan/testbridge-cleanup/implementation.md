# Единый Compose и очистка TestBridge

Цель — запускать все компоненты рабочего `testbridge` из одного Compose-файла, читать пароль Grafana из `secrets.yaml` и использовать рабочий стенд для интеграционных проверок.

- [x] **Tech-lead · Compose и пароль Grafana.** В едином `compose.yaml` сохранены 15 сервисов, порты и 10 томов. Сверка с прежней конфигурацией показала только удаление отдельного секрета Grafana. Bootstrap читает `grafana.password` из выбранного окружения в `secrets.yaml`.
- [x] **Tech-lead · Очистка репозитория.** Удалены дополнительный Compose-файл, `ci/`, корневой `Jenkinsfile`, `requirements-ci.lock` и CI-стадия в `Dockerfile`. Удаляемые пути исключены из индекса. Образ аналитики собрался штатно.
- [x] **Tech-lead · Правила и документация.** В `AGENTS.md` закреплены рабочие БД и существующий Jenkins, поправлены инструкции о миграциях. Описаны единый запуск и ротация учётных данных. [Конфигурация](../../configuration.md)
- [x] **Tech-lead · Рабочий стенд.** После применения Compose сохранены ревизия `0003_run_analytics`, 4 импорта, 5 результатов и 13 шагов. OpenAPI доступен с Windows и из агента Jenkins, Redis ответил `PONG`, Bull Board доступен. Пароль администратора применён через stdin к действующей SQLite. Подтверждены вход в Grafana, существующий дашборд и `up=1` через Grafana и VictoriaMetrics.
- [x] **Tech-lead · Очистка Docker.** Удалены 11 остановленных контейнеров по метке проекта `testbridge-orm`. Проверено наличие всех 6 томов старого проекта и 10 томов рабочего.

Ruff прошёл для `deploy`, `metrics_srv` и `tests`. В конфигурации и парсере прошли 29 тестов. Более широкий локальный прогон остановился на сборе тестов из-за отсутствия SQLAlchemy в установленном окружении. Сетевые проверки выполнены на рабочем стенде.
