# Планирование архитектуры Allure → Grafana

Цель: согласовать архитектуру и подготовить проверяемый план обработки результатов Allure и их отображения в Grafana с учётом Remnawave и текущего TestBridge.

Границы: первый этап — название теста, шаги и время; артефакты и фикстуры исключены. Реализация вне задачи планирования.

Критерии: изучены исходники Remnawave, текущий проект и образец архива; ключевые решения согласованы; план содержит этапы, зависимости и проверки.

- [ ] Analyst: изучить текущий проект; файлы на чтение: src/, docs/, конфигурация; зависимости: нет; проверка: ссылки на источники.
- [ ] Analyst: изучить Remnawave; источник: публичный репозиторий; зависимости: нет; проверка: ссылки на исходники.
- [ ] Analyst: изучить пример архива без раскрытия данных; источник: предоставленный ZIP; зависимости: нет; проверка: структура и агрегаты.
- [ ] Tech-lead: провести интервью и согласовать границы; файл: этот план; зависимости: результаты анализа; проверка: ответы пользователя.
- [ ] Tech-lead: подготовить план этапов и проверок; файл: этот план; зависимости: согласованные решения; проверка: соответствие источникам и критериям.

## Согласованные решения

- Новый проект; совместимость с существующим TestBridge не требуется.
- Python; разделение API, Scheduler и Processor заимствуется как принцип, выбор очереди открыт.
- Grafana первого этапа показывает общую статистику, а не детали отдельных тестов и шагов. Набор метрик требуется предложить.


## Факты исследования

- Пример — сформированный Allure Report: 9 data/test-cases JSON, все passed; raw allure-results отсутствуют. Шаги вложены в testStage.steps; фикстуры и вложения расположены отдельно. Ошибки и повторы примером не подтверждены.
- Remnawave (commit 6853666801d6d1925b6aec55824106100485777a): API, scheduler и processor — отдельные процессы; API также подключает очередь, так что строгую цепочку API → scheduler → processor считать подтверждённой нельзя. Valkey в примере запускается без persistence.

## Реализация по согласованному плану

Цель: принимать ZIP Allure через FastAPI, асинхронно разбирать результаты и сохранять тесты и вложенные шаги в PostgreSQL; удалять архив только после сохранения. Предоставленный архив содержит 9 исходных файлов `*-result.json` и сформированный отчёт: прежняя запись об отсутствии исходных результатов ошибочна.

Границы: Python, BullMQ/Redis, отдельные API/Scheduler/Processor, PostgreSQL, конфигурация YAML, Swagger, запуск Docker Compose. Grafana, метрики, фикстуры и вложения исключены. Критерии: согласованный API 202 и статус, безопасное сохранение/повторы/очистка, все 9 результатов, конфигурация и запуск Compose, документированный Swagger и пример Jenkins.

Решения в этом разделе заменяют устаревшие записи выше: очередь — BullMQ; Grafana, Collector, VictoriaMetrics и метрики в первый этап не входят.
