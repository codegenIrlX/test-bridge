# Реализация аналитики прогонов

Цель: реализовать `docs/plan/metrics-development/plan.md`, сохранив существующие API и данные. Результат: данные Allure и CI сохраняются, агрегаты доставляются через Collector в VictoriaMetrics и отображаются в Grafana; повторная обработка не удваивает данные.

Границы: существующие импорты сохраняются; фикстуры и вложения не обрабатываются. Проверка включает тесты, миграции, Compose и, при доступности, реальный Jenkins.

- [ ] **Architect:** определить контракт прогона и агрегации с учётом совместимости; файлы `docs/metrics-contract.md`; зависимость — исходный план; проверка — данные, повторы и отсутствие значений.
- [ ] **Developer:** реализовать сохранение данных Allure и метаданных прогона; файлы `metrics_srv/`, миграции и контракт API; зависимость — контракт; проверка — совместимость API и сохранность данных.
- [ ] **Developer:** реализовать агрегаты и экспорт; файлы приложения; зависимость — контракт данных; проверка — отсутствие двойного учёта.
- [ ] **Developer:** настроить Collector, VictoriaMetrics и Grafana; файлы Compose и конфигурации инфраструктуры; зависимость — контракт метрик; проверка — доставка и дашборд.
- [ ] **Tester:** покрыть парсер, API, агрегацию и миграции; файлы `tests/`; зависимости — контракты и реализация; проверка — pytest.
- [ ] **Reviewer:** независимо проверить корректность и риски; без правок; зависимость — реализация и проверки.
- [ ] **Tech-lead:** выполнить Ruff, тесты, интеграционную проверку и Jenkins при доступности; обновить этот план и сообщить ограничения.
