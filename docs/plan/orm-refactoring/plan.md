# TestBridge — архитектура импорта и переход на Alembic

Цель — одна начальная миграция для пустой PostgreSQL 17, SQLAlchemy 2.x с psycopg 3 и прикладные модули внутри `domains/imports`. Работа ведётся в `codex/import-reliability` поверх текущих изменений. Сохраняются API v1, статусы импорта, Jenkins, идемпотентность, ручной повтор и очистка независимо от Redis. Исторический коммит `5a3385c` служит источником решений для ORM и миграций.

Домен импорта включает HTTP-маршруты и DTO, сценарии приёма, обработки и очистки, репозиторий, ORM-модели, парсер и файловый адаптер. Общий пакет `db` предоставляет базу, mixin UUID и фабрику сессий. `workers` управляет Scheduler и Processor, `migrations` содержит окружение Alembic и ревизии. Точки входа остаются в `api.py` и `__main__.py`.

## Результаты приёмки

- На отдельной PostgreSQL 17 прошло 67 тестов. Два POSIX-теста файловых блокировок пропущены на Windows.
- На чистом Compose-проекте проверены ZIP через реальный Redis, вложенные шаги в PostgreSQL, очистка, повтор с тем же ключом и ответ 409 для другого ZIP. Повторный запуск мигратора из установленного пакета вне `/app` прошёл. В отдельном проекте завершение мигратора с кодом 23 оставило API, Scheduler и Processor в состоянии `created`. Проверочные контейнеры и тома удалены.
- Ruff для приложения, тестов и deploy, `git diff --check` и статическая проверка Compose прошли. Общий Ruff сообщает 21 прежнее замечание в примерах скилла `pytest-testing`.
