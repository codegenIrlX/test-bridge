# Конфигурация и запуск

Платформа читает настройки из `config.yaml`, а пароль PostgreSQL и токен API — из `secrets.yaml`. Перед запуском создайте `secrets.yaml` по образцу `secrets.example.yaml` и задайте собственные значения. Не добавляйте этот файл в Git и не передавайте его в контекст сборки образа.

В обоих файлах раздел `default` задаёт общие значения, а раздел выбранного окружения переопределяет их. Вложенные объекты объединяются по ключам. Окружение выбирается переменной `METRICS_SRV_ENV`; без неё используется `development`. Оба файла должны содержать раздел выбранного окружения, даже если он пуст. При отсутствии или неверном значении обязательных параметров процесс завершает запуск с ошибкой.

`config.yaml` содержит адреса и порты PostgreSQL и Redis, путь к архивам, пределы размера и количества файлов, а также интервал работы Scheduler. `secrets.yaml` содержит `database.password` и `api.token`. В Docker файл конфигурации монтируется только для чтения. Однократный контейнер читает Compose secret от имени root и копирует его в tmpfs с владельцем приложения и правами `0400`; остальным процессам tmpfs доступен только для чтения. Локально приложение читает `secrets.yaml` из рабочего каталога; внутри контейнера используется `/run/secrets/secrets.yaml`.

## Запуск с чистой базой

Начальная ревизия Alembic `0001_imports_orm` создаёт таблицы импорта на пустой PostgreSQL 17. Для перехода с прежней схемы запустите новый Compose-проект с отдельными томами PostgreSQL, Redis и архивов. Выберите свободное имя проекта, например `testbridge-orm`, и проверьте доступность портов хоста `8000` для API, `5433` для PostgreSQL и `3001` для Bull Board. При параллельном запуске задайте другие свободные порты через Compose override.

```sh
docker compose -p testbridge-orm config --quiet
docker compose -p testbridge-orm up -d --build
docker compose -p testbridge-orm ps -a
```

Проверьте, что `migrate` завершился с кодом `0`, а API, Scheduler и Processor запущены. Если Compose сообщает об ошибке миграции, проверьте `docker compose -p testbridge-orm logs migrate`. `migrate` ждёт готовности PostgreSQL (`service_healthy`) и выполняет `upgrade head`. Запуск трёх процессов зависит от успешного завершения мигратора (`service_completed_successfully`).

Данные PostgreSQL, очередь Redis и входящие архивы хранятся в именованных томах. Для запуска требуются Linux-контейнеры. Временные файлы для инициализации PostgreSQL создаются в отдельном томе tmpfs. Служебный контейнер удерживает тома tmpfs смонтированными между однократной подготовкой и запуском потребителей.

При запуске через Compose задайте `storage.path: /data/imports`. Compose монтирует общий том по этому пути в API, Scheduler и Processor и передаёт ожидаемый путь через `METRICS_SRV_REQUIRED_STORAGE_PATH`. При несовпадении конфигурация отклоняется до приёма архивов. При запуске без этой переменной путь задаётся в YAML.

Вне Compose выполните `python -m metrics_srv migrate` перед запуском приложения. Команда находит ревизии в установленном пакете независимо от рабочего каталога. `config.yaml` читается из рабочего каталога. При отсутствии `/run/secrets/secrets.yaml` там же читается `secrets.yaml`.

Откат начальной ревизии удаляет таблицы импорта, результатов и шагов вместе с их данными. Проверяйте `upgrade → downgrade → upgrade` на одноразовой базе.

## Эксплуатация

Если удалить обработанный ZIP не удалось, Scheduler повторит попытку спустя как минимум пять минут и продолжит очистку других архивов.

После изменения `secrets.yaml` выполните `docker compose -p testbridge-orm run --rm --no-deps secret-bootstrap`, затем `docker compose -p testbridge-orm restart api scheduler processor`. Процессы прочитают обновлённые настройки при запуске. После перезапуска Docker daemon или хоста выполните `docker compose -p testbridge-orm up -d`, чтобы снова запустить сервисы подготовки при очистке tmpfs. Используйте имя проекта и Compose-файлы, с которыми поднимали экземпляр.

Пароль из YAML используется при первоначальном создании базы. Изменение YAML не меняет пароль существующего пользователя PostgreSQL: ротация должна отдельно обновить пароль в БД и секрет приложения. Именованные тома не заменяют резервное копирование.
