# Feature-Sliced Design

Применяй FSD, когда проект уже использует методологию либо пользователь явно попросил её рассмотреть. Изучи фактическую версию, структуру, правила импортов и фреймворк; сохраняй принятые границы. Не перестраивай существующий проект и не создавай пустые слои только ради этого навыка. При проектировании или миграции сверяй спорные положения с [официальной документацией FSD](https://feature-sliced.design/docs).

Размещай код у фактического владельца и извлекай общую ответственность при подтверждённой потребности. Учитывай ответственность приложения, страниц, пользовательских действий, предметных сущностей и общей инфраструктуры в соответствии с выбранной версией FSD. Не считай любое повторение основанием для нового слоя.

Проверяй направление зависимостей, публичные границы и допустимость связей между срезами по правилам проекта. Если существующий код или фреймворк требуют исключения, объясни его и соблюдай принятый порядок фиксации решений. Для заметной миграции отдельно предложи план, стоимость, совместимость импортов и проверки. Для изменений UI применяй браузерную проверку проекта.

Обычно зависимости направлены от `app` и `pages` к нижележащим слоям `widgets`, `features`, `entities`, `shared`; не вводи отсутствующие слои. Срезы одного слоя не должны обращаться к внутренним файлам друг друга; используй публичные API и предусмотренные принятой версией механизмы для обоснованных связей. Общая инфраструктура не должна становиться владельцем произвольных доменных правил. Уточняй эти ориентиры по фактической версии и исключениям проекта.
