# Декомпозиция задач

Изучи запрос, доступные планы и решения, затронутый код и существующие проверки. PRD и GitHub не обязательны. Разбей согласованный объём на небольшие проверяемые результаты; при наличии сквозного пользовательского сценария предпочитай вертикальный срез. Укажи зависимости, критерии приёмки, применимые проверки и границы; не придумывай команды проекта.

По умолчанию подготовь локальный список с чекбоксами и сохрани его по указанному пути или принятой конвенции; если они не определены, представь список в ответе. Учитывай существующие задачи и не создавай дубликаты. Если статус дубликатов проверить невозможно, явно отметь ограничение.

GitHub issues создавай только по прямому запросу пользователя и после согласования конкретного списка, содержимого и целевого репозитория. Перед записью проверь доступные существующие issues и зависимости; при невозможности проверить дубликаты сообщи об этом и не утверждай, что их нет. Используй применимый инструмент GitHub; при неоднозначном результате проверь, создана ли задача, прежде чем повторять запрос. Не отправляй комментарии и не редактируй существующие issues без отдельного поручения. Покажи ссылки и результаты, включая частичные ошибки.
