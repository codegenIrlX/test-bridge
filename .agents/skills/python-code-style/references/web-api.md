# Python HTTP API и интеграции

Выбирай фреймворк и технологии по требованиям и принятому стеку проекта. Сохраняй существующие контракты и модель выполнения; HTTP API само по себе не требует БД, очереди или нового компонента. Структура и границы ответственности — в [правилах архитектуры](architecture.md), доменные DTO и JSON — в [правилах DTO](dto.md).

## Sync и async

- Рассматривай всю цепочку: обработчик, зависимости, драйверы, HTTP-клиенты, файловый I/O и вычисления. Выбирай sync или async по реальным библиотекам и характеру нагрузки.
- В FastAPI синхронные обработчики и зависимости выполняются в пуле потоков, но обычный блокирующий вызов внутри `async def` автоматически туда не переносится. При необходимости явно выделяй блокирующую работу, учитывая ограничения пула и потокобезопасность объектов.
- Отмена ожидающей корутины не гарантирует остановку уже запущенной работы в потоке. Учитывай это для побочных эффектов, таймаутов и освобождения ресурсов.
- Запускай параллельно только независимые операции; ограничивай их число возможностями пулов и внешних систем. Не используй одну изменяемую сессию БД одновременно в конкурентных задачах; соблюдай контракт драйвера и принятый lifecycle.
- Тяжёлые вычисления не ускоряются только от применения `async`. При подтверждённой потребности оцени процесс или worker и стоимость передачи данных.

## Жизненный цикл ресурсов

- Определи владельца общих клиентов и пулов, время их создания и закрытия. Используй lifecycle приложения и принятые механизмы внедрения зависимостей; в FastAPI учитывай существующий lifecycle и `lifespan`, когда он подходит.
- Не открывай соединения при импорте модуля. Переиспользуй общие ресурсы, когда это поддерживается клиентом; не храни сессии запроса и пользовательские данные в общем изменяемом состоянии.
- При частичной ошибке запуска освобождай уже созданные ресурсы; используй контекстные менеджеры или `ExitStack`/`AsyncExitStack`, когда они помогают. Проверяй закрытие при остановке и изоляцию запусков в тестах.
- Учитывай суммарное число соединений всех процессов и экземпляров, а также ограничения внешних сервисов.

## Надёжность интеграций

- Для внешних вызовов задавай подходящие таймауты подключения, чтения и ожидания ресурсов, учитывая общий срок сценария. Ограничивай конкурентность и ожидание при перегрузке.
- Повторяй только подходящие временные отказы: ограничивай число попыток и общий срок, используй задержку с увеличением интервала и случайным разбросом, учитывай `Retry-After`, когда применимо. Постоянный сбой не превращай в пустой успешный результат.
- До повтора учитывай идемпотентность и неопределённый результат предыдущей попытки. Если повтор может вызвать нежелательный эффект, определи механизм предотвращения дубликатов и хранение результата по требованиям сценария; не вводи ключи идемпотентности без потребности.
- Выбирай конкретные повторяемые исключения по контракту, не повторяй все `Exception` по умолчанию. Сохраняй отмену и сигнатуру декорируемой операции; проверяй ошибочную настройку числа попыток и итоговый отказ.
- Освобождай ресурсы при отмене и сохраняй полезную причину сбоя без раскрытия секретов. Проверяй таймаут, повтор, окончательный отказ и отмену для затронутых сценариев.

## Фоновые задачи

- Определи длительность работы, допустимость её потери при остановке процесса, необходимость восстановления и повторов. Короткая работа внутри процесса может быть достаточной, если её потеря допустима; FastAPI `BackgroundTasks` не является устойчивой очередью.
- При потребности в восстановлении, длительной обработке или независимом масштабировании оцени worker и подходящий механизм очереди. Определи предел повторов, таймаут, состояние, идемпотентность и порядок восстановления; worker управляет собственными ресурсами и не получает сессию завершённого запроса.
- Если запись в БД и публикация задачи должны быть согласованы, оцени надёжную передачу, например transactional outbox. Не обещай атомарность независимых систем без соответствующего механизма и не добавляй его без требования.

## Наблюдаемость и проверки

- Используй принятые механизмы логирования; не раскрывай секреты и персональные данные и не дублируй один сбой на каждой границе. Метрики выбирай по сценарию, например задержки, ошибки, ожидание соединений или backlog; избегай идентификаторов пользователей и других неограниченных значений в метках.
- Настраивай логирование централизованно на границе запуска; формат текста или структурированных событий выбирай по среде. Проверяй допустимые уровни и обработчики по конфигурации и не вводи JSON-логгер как обязательную зависимость.
- Если это нужно способу размещения, различай работоспособность процесса и готовность принимать запросы. Не подключай платформу мониторинга и не меняй формат логов только ради этого справочника.
- Проверяй входы, права, ответы и ошибки, совместимость потребителей и фактические контракты; для OpenAPI применяй существующий в проекте порядок сверки. Проверь lifecycle, частичный сбой запуска, отмену и окончательный отказ там, где изменяется соответствующее поведение.
- При изменении обработки ошибок проверяй применимые ожидаемые доменные и framework-отказы, входную и внутреннюю валидацию, неожиданный сбой, заголовки и отсутствие утечек. Сверяй фактические ответы с опубликованным OpenAPI; схема сама по себе не доказывает поведение обработчика.
- При изменении логирования проверяй изоляцию и сброс контекста запросов, отсутствие чувствительных данных в применимых приёмниках и traceback, дубли и корректность событий после подтверждённого результата. Учитывай фактические механизмы проекта; отдельная проверка примера не доказывает работу всей системы журналирования.
- Свойства ограничений, транзакций и изоляции проверяй на подходящей тестовой БД: mock не подтверждает работу СУБД. Для изменений производительности сравни результаты на представительном стенде, не выдавая один запрос за нагрузочный тест.
- Для сравнения производительности используй одинаковый представительный сценарий и условия до и после изменения. При изменении конкурентности или лимитов оцени применимую нагрузку, задержки, ошибки и ресурсы; сообщай ограничения стенда.
