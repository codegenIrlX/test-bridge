# Доменные DTO и JSON-контракты

## Размещение и владение

- Храни доменные DTO внутри домена-владельца в `dto/<назначение>/`, включая небольшие проекты с доменными API-контрактами. Единый доменный `dto.py` не заменяет это разделение.
- Разделяй назначения: `create`, `update`, `read`, `list` и другие реально используемые операции. Внутри назначения допустимы соответствующие request и response; DTO разных назначений не располагаются рядом в корне `dto/`.
- Один DTO-класс определяется в одном Python-файле. Это включает request, response, вложенные модели, элементы списков, базовые DTO и generic-контейнеры. Например, `create_resource_request.py` определяет только `CreateResourceRequestDto`; остальные DTO импортируются из собственных модулей.
- Не переноси доменные контракты в `shared/dto`. Общая переиспользуемость сама по себе не меняет владельца; другие домены используют его опубликованный контракт без независимых копий и циклических импортов.

```text
domains/resources/dto/
  create/
    create_resource_request.py
    create_resource_response.py
  update/
    update_resource_request.py
  read/
    resource_response.py
  list/
    resource_list_response.py
    resource_list_item_response.py
```

`resources` — пример владельца. Корневой пакет, `src/` layout и названия других назначений выбираются по реальному проекту. Для базовых и generic DTO выбирай реальное назначение у владельца; не создавай общий пакет только ради наследования. Технический базовый класс без доменных полей размещай по принятой инфраструктуре проекта; это не повод переносить туда доменные контракты. В любом случае сохраняется правило одного DTO-класса на файл.

## Docstring и описания полей

- Каждый DTO-класс имеет собственный краткий docstring на русском языке. Это относится к request/response DTO, вложенным моделям, элементам списков, базовым DTO, generic-контейнерам и техническим DTO. Унаследованное описание не заменяет docstring нового класса.
- Описывай назначение данных понятными читателю словами. Обычно достаточно одного предложения: `"""Регион присутствия оператора."""` или `"""Список регионов с данными о странице."""`. Существенные условия использования добавляй отдельно, без пересказа структуры класса и выдуманных гарантий.
- Каждое поле Pydantic DTO описывай через `Field(description=...)` независимо от docstring класса. При наследовании описание сохраняется у объявления поля; для переопределённого или нового поля укажи собственное описание. Docstring не заменяет описания полей и ограничения валидации: сохраняй заданные ограничения и значения по умолчанию.
- При изменении существующих контрактов сохраняй актуальные описания и совместимость сериализации, aliases и валидации. Если проверенный источник описания поля существует в проекте, используй его; не придумывай неподтверждённый смысл или гарантию.

## Именование

Каждый Pydantic-класс доменного публичного или внутреннего API-контракта имеет суффикс `Dto` и имя в `PascalCase`. Файлы и каталоги остаются в `snake_case`.

Имя показывает назначение и область данных. Не используй неоднозначные `UserData`, `CreateUser` или `UserResponse`.

| Роль | Правило | Пример |
| --- | --- | --- |
| Входящее тело запроса | `RequestDto` | `CreateResourceRequestDto` |
| Ответ API | `ResponseDto` | `ResourceResponseDto` |
| Контейнер списка ответа | `ListResponseDto` | `ResourceListResponseDto` |
| Элемент списка ответа | `ListItemResponseDto` | `ResourceListItemResponseDto` |
| Bulk-запрос | Действие + область + `RequestDto` | `BulkRevokeUsersSubscriptionRequestDto` |
| Bulk-ответ | Действие + область + `ResponseDto` | `BulkRevokeUsersSubscriptionResponseDto` |
| Внутренний контракт другого назначения | Понятное назначение + `Dto` | `ResourceExportRowDto` |

Правило относится к моделям API-контрактов. Оно не требует превращать ORM-модели, настройки или обычные внутренние объекты в Pydantic DTO. Существующие имена и import paths меняй с учётом потребителей, а не механическим переименованием.

## FastAPI: JSON в camelCase

При использовании FastAPI именованные JSON-поля запросов и ответов оформляй в camelCase, например `resourceId` и `groupId`. Python-атрибуты, аргументы и поля БД сохраняй в snake_case: `resource_id`, `group_id`. Это соглашение о контракте проекта, а не автоматическое свойство FastAPI.

- Проверь версии FastAPI/Pydantic и существующую конфигурацию до выбора API настройки. Используй aliases или генератор aliases для JSON-полей; различай aliases валидации и сериализации.
- Для Pydantic 2 возможен `alias_generator=to_camel` в `ConfigDict`. Учитывай явные aliases полей и вложенные DTO: настройка внешнего контейнера сама по себе не переименовывает поля отдельно определённой вложенной модели.
- Проверяй входной JSON и выходной JSON отдельно. При ручном `model_dump`/`model_dump_json` явно учитывай `by_alias=True` либо принятую настройку сериализации по aliases. `mode="json"` сам по себе не включает aliases.
- Настройки `validate_by_alias`, `validate_by_name` и `serialize_by_alias` доступны с Pydantic 2.11; не применяй их к старым версиям и не обновляй зависимости автоматически. Поддержку snake_case-входа выбирай по требованиям совместимости, а не включай без необходимости.
- Проверь, что настройки response model, включая `response_model_by_alias`, не возвращают Python-имена вместо внешних aliases.
- Прямой `Response`/`JSONResponse` обходит автоматическую валидацию и сериализацию модели FastAPI. Подготовь сериализованный по aliases JSON-совместимый payload сам и отрази контракт в OpenAPI принятым способом. Учитывай datetime и другие значения, которые требуют JSON-преобразования.
- Сверяй фактические запросы и ответы с OpenAPI, включая вложенные объекты, списки и изменённые JSON-ошибки. Проверяй исходный JSON до нормализации клиентом; одна корректная схема не доказывает правильность runtime-ответа.

## Совместимость и границы

Не меняй опубликованный wire-format без согласованного перехода. Не переименовывай автоматически протокольные и сторонние поля, например OAuth `access_token`, `token_type`, `grant_type`, значения enum, машинные коды ошибок и динамические ключи словарей. Конкретное исключение должно следовать контракту, а не случайному стилю соседнего поля.

Правило JSON не задаёт новый формат query/path-параметров, заголовков, cookie, переменных окружения или SQL. Для них сохраняй соглашения реального проекта. FastAPI и Pydantic не становятся обязательными для Python-проектов без соответствующих контрактов.
