# Конфигурация проверок Python

Примеры предназначены для адаптации: сохрани существующие инструменты, настройки, hooks и lock-файлы проекта. До изменений выясни поддерживаемый Python, расположение кода и тестов, версии локальных и CI-инструментов и правила уже подключённых hooks. Не добавляй зависимости или hooks только ради примера.

## Зависимости и типизация

Группируй инструменты разработки по принятому менеджеру зависимостей; поддерживай согласованные версии с CI и hooks и воспроизводимое разрешение через принятый lock-файл. Не навязывай Poetry. Для нового кода выбирай строгую типизацию по задаче; в существующем проекте расширяй покрытие постепенно, сохраняя работающую конфигурацию. Не исключай тесты или не подавляй отсутствующие импорты глобально без обоснования; отдельные исключения ограничивай точным модулем и объясняй.

## Ruff

Для нового Python-проекта, где выбран Ruff, возможен такой фрагмент `pyproject.toml`:

```toml
[dependency-groups]
dev = ["ruff"]

[tool.ruff]
line-length = 120

[tool.ruff.lint]
select = ["E", "F", "I"]
```

Это отправная точка, а не обязательная конфигурация. `E` включает правила pycodestyle, `F` — Pyflakes, `I` — сортировку импортов. Выбирай версию Ruff, совместимую с Python и инструментами проекта, и фиксируй её принятым способом. Группу `dependency-groups` используй, только если её поддерживает менеджер проекта; иначе добавь Ruff в принятую группу разработки. Сохраняй существующие правила и оцени влияние изменений на локальные проверки и CI.

`line-length = 120` задаёт целевую длину для форматтера и лимит по умолчанию для `E501`; выбор `E` включает `E501`. Форматтер не гарантирует разбиение всех длинных строк, а `E501` имеет документированные исключения. Проверяй оставшиеся замечания вручную; при необходимости согласуй адресные исключения вместо массовых подавлений. В другом проекте сохраняй его принятую длину строки.

Запусти `ruff check <пути>` и, если проект использует форматтер Ruff, `ruff format --check <пути>`: эти команды проверяют без изменения файлов. Для применения согласованных исправлений сначала используй `ruff check --fix <пути>`, затем `ruff format <пути>` и повтори проверки; изучай изменения и не применяй `--unsafe-fixes` без отдельной оценки. Пути выбирай по фактическому проекту, включая нужные скрытые каталоги и исключая посторонние файлы. До включения дополнительных правил сравни их результаты на реальном коде с пользой и объёмом изменений; не добавляй группы механически.

Область проверки, правила, длину строки и поддерживаемую версию Python определяй по проекту; при необходимости задавай `target-version`. Ruff может вывести минимум из `requires-python` в зависимости от способа обнаружения конфигурации; проверь фактически выбранную настройку. Новые игнорирования не должны скрывать ошибки без причины.

## Mypy

Пример фрагмента для нового проекта:

```toml

[tool.mypy]
warn_unused_configs = true
warn_unused_ignores = true
check_untyped_defs = true
disallow_untyped_defs = true
```

Отдельные ограничения mypy задавай для конкретных модулей.

## Pre-commit

При наличии установленных в окружении проекта `ruff` и `mypy` возможен локальный вариант:

```yaml
repos:
  - repo: local
    hooks:
      - id: ruff-check
        name: Ruff lint
        entry: ruff check
        language: system
        types_or: [python, pyi]
      - id: ruff-format
        name: Ruff format check
        entry: ruff format --check
        language: system
        types_or: [python, pyi]
      - id: mypy
        name: Mypy
        entry: mypy src
        language: system
        pass_filenames: false
        types_or: [python, pyi]
```

Здесь `src` — пример: замени его фактическим пакетом. `language: system` использует инструменты активного окружения, поэтому зафиксируй версии в менеджере проекта и обеспечь такое же окружение в CI. Если применяешь отдельный hook-репозиторий, согласуй его `rev` с локальным Ruff и обновляй осознанно. Порядок lint и проверки форматирования должен соответствовать проекту; предложенный вариант не исправляет файлы. Существующие hooks не заменяй и не устанавливай автоматически. `pre-commit run --all-files` может менять файлы, если другие hooks это делают; изучи цепочку до запуска.

Источники: [Ruff configuration](https://docs.astral.sh/ruff/configuration/), [Ruff formatter](https://docs.astral.sh/ruff/formatter/), [E501](https://docs.astral.sh/ruff/rules/line-too-long/), [pre-commit](https://pre-commit.com/), [mypy configuration](https://mypy.readthedocs.io/en/stable/config_file.html).
