# План реализации

Изучи запрос, применимые инструкции, доступные PRD и решения, связанные участки кода, контракты, данные и проверки. PRD не обязателен. Принятые решения учитывай как ограничения; конфликт с ними или кодом показывай с источниками и последствиями. Отделяй подтверждённое от допущений.

Опиши цель, границы, точки интеграции, изменения и проверки. Для многоэтапной функции предпочитай небольшие вертикальные этапы с наблюдаемым результатом; инфраструктурный этап допустим, если он необходим и его результат самостоятельно проверяем. Не объявляй заглушку работающей интеграцией.

Соблюдай установленный порядок согласования: при неопределённом объёме сначала предложи каркас и согласуй его, не повторяя уже полученного согласия. Подробный план оформляй по [шаблону](references/template.md) или принятому формату. Укажи реальные команды либо обозначь отсутствующие проверки, не называя планируемое выполненным. Сохрани по указанному пути или конвенции проекта; если они не определены, представь план в ответе. Планирование само по себе не разрешает реализацию.
