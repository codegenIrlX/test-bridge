# UML sequence

Покажи один метод или связный сценарий. В заголовке укажи реальный метод и путь API либо название взаимодействия. [Основа sequence](../assets/sequence.drawio) содержит только нейтральные элементы оформления; её участники и сообщения не являются контрактом проекта.

## Участники и порядок

- Участник — реальная система, процесс или значимый компонент выбранного уровня. Сообщение направляй фактическому исполнителю. Не относись к модулю как к отдельному сервису, если он работает внутри процесса.
- Время идёт сверху вниз. Вызовы, ответы, активации, синхронные и асинхронные сообщения различай по UML. Активация не должна начинаться до вызова или продолжаться после завершения в показанном пути.
- Для API сверь транспортные ограничения, авторизацию, валидацию, побочные эффекты, обращения к данным и ответ по реализации либо выбранному контракту. Укажи подтверждённые HTTP-статусы и значимые заголовки; не превращай общий список OpenAPI в якобы реализованные проверки.
- Проверки должны сохранять фактический порядок. Ранний отказ исключает зависимые действия; не показывай сравнение checksum после ошибки, которая уже прервала чтение.
- Возврат успешного ответа, COMMIT и завершение фоновой обработки — разные события. Не навязывай фоновой задаче порядок после сетевого ответа, если такого отношения код или контракт не гарантирует.

## Ветвления и ошибки

Используй `alt` для альтернатив, `opt` для необязательного пути, `loop` для повторения, `par` для подтверждённой параллельности, `break` для завершения оставшейся части взаимодействия при условии отказа. Условия пиши в квадратных скобках. Ветви должны быть различимы; различай новый запрос, идентичный повтор и конфликт, учитывая порядок проверок.

Выбирай ошибки в пределах задачи; схема не обязана перечислять все возможные сбои. Не обещай rollback файлов, транзакцию или автоматический retry без источника. Если показана очистка, проверь её исполнителя, условия и положение относительно отказа, фиксации и ответа. Исключение, ответ с ошибкой и успешный результат не должны сливаться в один безусловный путь.

Проверь каждый показанный путь отдельно. Ранний выход не продолжается ниже `break`; альтернативы не выполняются подряд. Отметь вне схемы границы рассмотренных отказов, если полнота может быть понята неверно.

Основа нотации: [OMG UML 2.5.1](https://www.omg.org/spec/UML/2.5.1), раздел Interactions.
