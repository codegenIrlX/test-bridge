# Workflow: координатор + субагенты

## Общий принцип

Главная сессия — координатор (`tech-lead`). Субагенты работают в своей зоне и возвращают результаты **только ответом**, не передавая между собой временные рабочие документы. Координатор пересылает полные ответы, ведёт отдельный счётчик итераций ревью и прогонов.

| Агент | Область ответственности |
|-------|------------------------|
| `tech-lead` | Планирование, координация, приёмка результатов |
| `analyst` | Уточнение требований, критерии приёмки |
| `architect` | Проектирование границ, API, данных, схемы |
| `developer` | Реализация в приложении, миграциях, конфигурации |
| `tester` | Тесты, проверка критериев приёмки |
| `reviewer` | Независимое ревью кода, поиск дефектов |

## Потоки работы

### 1. Разработка новой фичи

1. Координатор проверяет рабочее дерево (`git status`), создаёт/использует ветку `feat/<название>`
2. `analyst` формулирует требования и критерии приёмки
3. `architect` проектирует изменения (при необходимости)
4. `developer` реализует код
5. `reviewer` проверяет изменения — максимум **3 цикла ревью**
6. `tester` добавляет/обновляет тесты — максимум **3 цикла прогона**
7. Координатор коммитит по согласованию

### 2. Ревью кода

Вход: diff, MR, либо явный набор файлов. Координатор определяет точную область, вызывает `reviewer`. **Код не меняется, тесты не запускаются, коммита нет.**

### 3. Тестирование

Вход: путь, nodeid, маркер. Координатор вызывает `tester` с конкретной областью. После правок — повторный `reviewer` → прогон.

### 4. Починка

1. `tester` воспроизводит падение и классифицирует: `TEST_BUG`, `TEST_INFRA_BUG`, `PRODUCT_BUG`, `ENVIRONMENT`, `UNKNOWN`
2. `PRODUCT_BUG`/`ENVIRONMENT`/`UNKNOWN` → сообщить, не чинить вслепую
3. `TEST_BUG`/`TEST_INFRA_BUG` → `developer`/`tester` → `reviewer` → прогон

## Вердикты

- `reviewer`: `OK` или замечания `blocker`/`major`/`minor`
- `tester`: `GREEN` (всё прошло) / `RED` (есть падения) / `BLOCKED` (среда)
- Координатор: `READY` (можно коммитить) / `PARTIAL` / `BLOCKED`

## Git

- Ветки: `feat/<name>`, `fix/<name>`, `refactor/<name>`, `test/<name>`, `docs/<name>`, `chore/<name>`
- Основание: `dev`
- Коммит: conventional format, согласовать заголовок и состав
- Не коммитить секреты, `.secrets.yaml` с реальными значениями
- Push — только по просьбе пользователя
