# Адаптация агента в проекте TestBridge

Выполняется локально в целевом репозитории. Перед первой задачей агент должен прочитать этот файл и создать/обновить `.opencode/docs/project-map.md` на основании реально прочитанного кода.

## Порядок адаптации

1. Прочитать корневой `AGENTS.md`
2. Прочитать `.opencode/docs/workflow.md` — процесс работы
3. Прочитать `.opencode/docs/style-decisions.md` — согласованные правила
4. Исследовать структуру проекта:
   - `metrics_srv/` — доменные модули, API, БД
   - `tests/` — тесты
   - `deploy/` — эксплуатационные файлы
   - `compose.yaml` — инфраструктура
   - `pyproject.toml` — зависимости
5. Найти примеры:
   - API endpoint (FastAPI router)
   - DTO/Pydantic модель
   - SQLAlchemy model
   - Unit/интеграционный тест
   - Alembic миграция
   - Worker (scheduler/processor)
6. Записать в `.opencode/docs/project-map.md`:
   - Реальные пути и символы
   - Примеры использования
   - Команды проверки (`ruff check .`, `pytest`)
   - Зависимости и версии
   - Особенности и ограничения

## Конфликтующие инструкции

Если старые инструкции (в том числе из `.codex/` или корневых файлов) противоречат настоящему комплекту — приоритет имеет:
1. Явная спецификация пользователя
2. `.opencode/docs/style-decisions.md` и `.opencode/docs/workflow.md`
3. `AGENTS.md`
4. Фактический код проекта

## Проверка качества

Первый прогон: одна реальная задача → карта переиспользования → реализация → ревью → проверки.
Сравнить с прежним результатом: нарушения слоёв, дублирование, недостающие проверки.
